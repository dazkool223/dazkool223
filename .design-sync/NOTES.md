# design-sync notes for dazkool223 (portfolio)

## Scope: primitives only, not the whole app

This repo is a Next.js 16 personal-portfolio app, not a component-library
package - no Storybook, no `dist/` build, no `.d.ts` exports. Most of
`src/components/` and all of `src/components/sections/` are one-off page
sections hardwired to `src/lib/data.ts` content (Hero, Readme, Worklog,
Studio, Footer, Experiments) or global page effects (Preloader, Console,
Cursor, SmoothScroll, Nav, GridOverlay's `<html>`-level listeners). None of
that is a reusable building block, so the sync is deliberately scoped to
just 7 presentational primitives via `.design-sync/entry.mjs` +
`cfg.componentSrcMap`: Reveal, Magnetic, SectionHeading, Marquee,
GridOverlay, ToolbenchPanel, FieldNotesStrip.

Adding a component to the design system later: add it to both
`.design-sync/entry.mjs` (re-export) and `cfg.componentSrcMap` in
config.json, then re-run the build. Don't point `cfg.srcDir` at the whole
`src/` tree - the package-shape synth-entry fallback
(`deriveComponentsFromSrc`) would sweep in every PascalCase export across
the app, including `src/app/layout.tsx`'s `RootLayout` (imports
`next/font/google`, a Next-compiler-only macro that breaks under plain
esbuild) and page components like `Home`/`Page`.

## Fonts: promoted to :root from the real compiled CSS

The site loads its 3 brand fonts (Space Grotesk, IBM Plex Mono, Newsreader)
via `next/font/google` in `src/app/layout.tsx`. next/font sets
`--font-grotesk`/`--font-plex`/`--font-newsreader` only on a hashed
CSS-module class applied to `<html>` - design-sync previews never render
inside that wrapper, so without intervention every preview would silently
fall back to system-ui/monospace/serif.

Fix: `cfg.cssEntry` points at `.next/static/chunks/_ds-styles.css`,
generated by `.design-sync/prepare-css.mjs` from the real `next build`
output with the same `--font-grotesk`/etc. values (copied verbatim from the
compiled chunk's own `*__variable` rule, not invented) promoted to a plain
`:root` block. This also means the real `@font-face` rules + actual woff2
files ship (via the converter's own `extractFonts`, which finds them
through the chunk's relative `url(../media/...)` references) - not a
Google Fonts CDN substitute, the exact same self-hosted files the live site
serves.

**Re-sync risk**: `npm run build`'s output filename is content-hashed and
changes every build - `prepare-css.mjs` always writes the stable
`_ds-styles.css` alongside it, so `cfg.cssEntry` never needs to change, but
you MUST re-run `cfg.buildCmd` (`npm run build && node
.design-sync/prepare-css.mjs`) before every re-sync, not just when the DS
components themselves changed - a Tailwind utility class added anywhere in
the app (not just the 7 synced components) regenerates the compiled CSS
those 7 draw from.

## Tailwind v4 needs a real build, not raw globals.css

`src/app/globals.css` is Tailwind v4 *source* (`@import "tailwindcss"` +
`@theme inline` token definitions) - almost none of the component styling
is hand-written CSS; it's Tailwind utility classes generated by the
build's content scan. Copying globals.css raw would ship only the ~10
hand-written utility classes (`.label-mono`, `.annotation`, `.rule`, ...)
and none of the `grid`/`gap-*`/`text-accent`/`border-line`/etc. utilities
every component actually uses. Hence the real `next build` dependency
above.

## Design tokens

No separate tokens package - the real color tokens (`--bg`, `--surface`,
`--ink`, `--muted`, `--faint`, `--line`, `--accent`, `--accent-dim`) are
defined directly in `globals.css`'s `:root`/`@theme inline` blocks and ship
as part of the same compiled `cssEntry` chunk. No `cfg.tokensGlob` needed.

## Known render warns

- `[RENDER_BLANK]` on `GridOverlay`'s `Visible` story: false positive. The
  grid overlay is an intentionally faint (6-20% opacity) decoration, so its
  screenshot compresses under the 5KB "likely blank" heuristic even though
  the grid lines genuinely render (confirmed visually - a dark background
  with thin orange-tinted column dividers fills the frame). Composition
  dispatches the real `keydown "g"` the component listens for since no prop
  can force it open; a `position:fixed` wrapper was tried first and
  collapsed the measured screenshot height entirely (real bug, not this
  one) - reverted to a normal-flow wrapper with an explicit height that
  matches the `cfg.overrides.GridOverlay.viewport`.

## Re-sync risks (forward-looking)

- The font-vars values in `prepare-css.mjs` are hand-copied from one
  observed build's output. If the site ever changes font weights/styles in
  `layout.tsx`'s `next/font/google` calls, or switches away from
  next/font, re-verify the `--font-*` fallback-name strings still match.
- `componentSrcMap` pins 7 exact paths. If any of these 7 files move or get
  renamed, update both the pin and `.design-sync/entry.mjs`'s import path.
- Nothing here has been through the render-check/preview-authoring loop
  yet - this file will grow as that work happens.
